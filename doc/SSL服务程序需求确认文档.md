#### 已确认方向的证书目录结构

```text
/ssl/{域名}/
├── production/                 生产证书
│   ├── wildcard/               泛域名证书，例如 *.example.com
│   │   ├── current/            当前使用版本
│   │   └── versions/{版本}/    历史版本
│   └── single/                 单域名证书，例如 example.com
│       ├── current/
│       └── versions/{版本}/
└── development/                开发证书，目录结构与 production 相同
```

多域名 SAN 证书纳入第一阶段，证书以主域名作为管理归属，并保存完整的 SAN 域名集合。SAN 证书目录使用证书标识区分不同域名集合：

```text
/ssl/{主域名}/
├── production/
│   ├── wildcard/
│   ├── single/
│   └── san/{证书标识}/
│       ├── current/
│       └── versions/{版本}/
└── development/
    ├── wildcard/
    ├── single/
    └── san/{证书标识}/
        ├── current/
        └── versions/{版本}/
```

其中 `{证书标识}` 必须能够稳定对应主域名和 SAN 域名集合；域名集合发生变化时创建新的证书版本，不覆盖原有证书版本。

```text
11. 使用 Let’s Encrypt 和 `go-acme/lego` 通过 DNS-01 申请管理后台证书
12. 校验并安装本地 HTTPS 证书
13. 启动前后端均纳入 HTTPS 部署的管理后台
14. 标记初始化完成
```

### 5.2 自动续期流程

```text
1. 调度器按每 3 天一次的常规周期检查证书；剩余有效期低于 10 天时改为每天检查
2. 证书剩余有效期低于 6 天时创建续期任务；低于 3 天时按紧急策略重试
3. 申请任务进入串行队列，同一时间只运行一个申请任务
4. 检查 DNS 配置、DNS Zone、权限和 ACME 账户
5. 调用 `go-acme/lego` 使用 Let’s Encrypt 创建 ACME Order
6. 创建或委派 DNS TXT 记录
7. 等待并检测 DNS 记录传播
8. 执行 ACME DNS-01 验证并下载新证书
9. 校验新证书和私钥
10. 保存新的本地证书版本
11. 部署到关联服务器并执行 Web 服务器或反向代理检查、reload
12. 检查所有 A/AAAA 记录并执行远程 HTTPS 校验
13. 校验失败或部署失败时恢复旧版本
14. 按默认 3 次、每次间隔 30 分钟的策略重试；用户可自定义续期时间和重试次数
15. 写入任务和审计日志，并发送 HTTP/SMTP 任务通知
```

### 5.3 用户证书部署流程

```text
1. 上传证书和私钥
2. 校验文件格式
3. 校验证书和私钥匹配
4. 校验证书域名和有效期
5. 保存为新版本
6. 用户手动确认部署
7. 部署到关联服务器
8. 执行目标 Web 服务器或反向代理检查和 reload
9. 执行 HTTPS 校验
10. 记录结果并发送通知
```

## 七、需求确认结果与待确认事项

本节已根据前述用户补充区更新。已确认内容作为正式需求依据，未确认内容不得在实现阶段擅自假设。

### 7.1 已确认的关键结论

1. 第一阶段使用 Let’s Encrypt 作为 ACME CA，并使用 `go-acme/lego` 负责申请、DNS-01 验证和自动续期；其他 ACME CA 仅预留后续扩展能力。
2. 第一阶段支持 Cloudflare、阿里云 DNS、DNSPod、CNAME 委派、华为云、腾讯云、AWS Route 53、Google Cloud DNS 及其他服务商适配器；CNAME 委派自动创建失败时提示用户手动创建。
3. 第一阶段同时保留 HTTP API 和 SMTP 通知方式；SMTP、IMAP、POP3 协议表仅作为外部邮件服务兼容性参考，Scert 通过外部 API 调用邮件发送服务，不实现邮件服务器端。
4. 管理后台采用双 HTTPS 模式：默认由核心服务直接终止 HTTPS；高级模式由 Nginx/Caddy 终止公网 HTTPS，核心服务使用内部 HTTPS。
5. 续期策略为：每 3 天常规检查一次，剩余有效期低于 10 天时每天检查，低于 6 天触发续期，低于 3 天进入紧急重试；默认重试 3 次、每次间隔 30 分钟，用户可自定义续期时间和重试次数。
6. 泛域名证书只申请 `*.example.com` 形式的泛域名，不自动包含 `example.com` 根域名。
7. CNAME 委派默认由程序自动创建；自动创建失败时，必须向用户展示记录并提示手动创建。
8. 第一阶段不限定远程目标为 Linux Nginx；默认支持 Nginx，并适配主流 Windows/Linux Web 服务器和反向代理软件。
9. 桌面版采用 Web 管理界面封装，由桌面版启动本地核心服务，并提供系统托盘、后台任务状态和可选开机自启动。
10. 协议连接表仅作为外部邮件服务兼容性参考；通知接口支持用户自定义地址、Bearer Token、HMAC-SHA256、无认证测试模式、详细/统一事件、自定义请求头、2xx 成功判定和可配置重试。
11. 多域名 SAN 证书纳入第一阶段，使用主域名作为管理归属并保存完整 SAN 域名集合；域名集合变化时生成新的证书版本。
12. 数据库支持 MySQL 和 SQLite；MySQL 5.7 作为基础开发和最低兼容版本，MySQL 8.0 作为兼容性测试版本，SQLite 用于单机、桌面和开发模式。
13. Linux 默认使用 `/ssl`、`/scert`、`/scert/conf`、`/scert/log`、`/scert/backups`；创建专用 `Scert` 服务运行用户管理证书目录，私钥由 `Scert` 和 `root` 共同受控管理。Windows 按自定义安装目录使用 `Scert\\ssl`、`Scert\\data`、`Scert\\config`、`Scert\\logs`、`Scert\\backups`。
