## 关键设计与续接注意事项

### 配置提交边界

`Config.Save` 只有正式文件替换成功才返回成功，替换之后不再执行可能返回错误的权限操作，避免调用方错误回滚已提交的证书和凭据。代码不保证断电后的目录项持久性；Linux 目录归属及权限准备仍可能产生元数据副作用。

### 验证凭据的事务所有权

`Claim` 在验证管理器的互斥锁下读取并移除有效令牌，返回验证结果和仅能执行一次的失败回收函数。`Completer` 成功保存配置后不调用回收函数；任何提交前失败都尝试回收。旧 `Resolve`、`Check`、`Consume` 保留给原有调用方，但新 Bootstrap 提交不再采用“先读取、最后消费”的模式。

此机制覆盖当前进程内的受控失败，不承诺进程强制终止后的孤立临时凭据自动恢复；后续启动清理机制应单独复审。数据库迁移和管理员写入可能已发生，不能宣称所有数据库副作用可回滚。

### 通知兼容

完成请求通过可选 `notification` 对象传递通知配置。省略对象保留原有配置，提供对象按完整表单应用；客户端不能指定 `http_credential_ref` 或 `smtp_credential_ref`。HTTP 支持 Bearer、HMAC-SHA256 和账号会话认证；SMTP 密码单独存储。

前端现已将原通知表单映射到该对象，通知步骤保留。不要把客户端输入或底层错误写入公开响应。

### 三库运维边界

新增数据库加密引用后，MySQL 维护操作必须在内存中解密账号再建立连接，不能直接使用无账号的持久化 DSN。恢复前应固定可用连接，避免配置和主密钥替换过程中失去快照或回滚连接。备份校验必须包括数据库凭据引用。

PostgreSQL 原完整备份实现只有 SQLite/MySQL，前序版本先采用明确拒绝保护。2026-09-16 本轮已接入官方 `pg_dump`/`pg_restore`：要求同主版本且至少为 16，生成自定义归档并完整解码校验，配置、加密凭据、证书共同纳入备份清单。缺工具、解码失败或快照失败不能发布备份。

自动恢复只支持相同目标及严格一致的对象清单，保留所有者和授权；先保存当前数据库快照，再以单事务导入，后续证书或凭据失败则恢复原数据。MySQL 和 PostgreSQL 回滚不再沿用已取消请求，改用独立五分钟超时。空库灾难恢复、跨结构版本恢复仍需原生工具和管理员流程。详细前提、保密边界及限制见 `PostgreSQL备份恢复说明.md`；本地替身测试不能替代真实恢复演练。

### PostgreSQL 连接串安全边界

驱动实际会让 URL 查询中的 `user`、`password` 覆盖用户信息部分。旧检查仅检查用户信息，导致查询中的明文凭据可以保存，连接时还可能覆盖已解密的账号。本轮先通过失败回归复现，再把校验集中到 `config.ValidatePostgresDSN`，配置保存、凭据解析和 URL 运行时连接共用边界。

拒绝查询中的账号、密码、客户端私钥密码、目标主机/端口/数据库覆盖及额外凭据文件来源；拒绝重复参数、混合大小写参数、无效编码和片段。继续允许正常 TLS 根证书、连接超时和应用名称等参数，合法配置可保存并重新加载，特殊字符密码经 URL 编码后与驱动解析值一致。

PostgreSQL 连接串日志辅助函数改为整体隐藏，解析失败不返回驱动原始连接串。拒绝无效配置时不读取凭据、不写入配置文件。这里的修复没有实现 PostgreSQL 备份恢复，也不证明数据库环境、连接权限和证书已在实机验收。

### 验收与操作边界

- 新启动链路已接入 `scert serve`，但独立服务的实际页面渲染和新版本 Linux 部署仍未验收。
- IP 管理入口目前使用自签名证书，不能表述为已获公共 CA 信任。
- Bootstrap 临时证书仅保存在进程内；启动日志提供实际证书 SHA-256 指纹，管理员须通过可信 SSH/控制台与浏览器核对，不一致则停止。每次未初始化服务重启都会生成新证书，不能复用旧指纹。
- Linux 固定及动态 systemd unit 显式选择 `SCERT_BOOTSTRAP_FIREWALL_MODE=external`，保留非特权 `Scert` 用户和空网络管理能力集。外部策略不查询、不写入规则，日志及完成响应提示管理员预先配置端口；不证明端口已放行。命令行默认 `auto` 仍失败关闭，操作限时三十秒，不能因权限错误悄悄降级或要求服务提权。
