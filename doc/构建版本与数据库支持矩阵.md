### 构建机与安装策略

| 项目 | 固定基线或约束 | 验收边界 |
|---|---|---|
| 当前 Windows 构建机 | Windows 11 Home China，系统 `10.0.26200`，amd64；Windows PowerShell 5.1 | 记录实际值，不把系统显示名称误写成内核版本；系统更新后需重新验收 |
| Linux 原生构建机 | 脚本允许 Linux amd64，但尚无本批指定发行版、内核、PowerShell 版本的原生构建证据 | 不宣称 Linux 原生可重复构建已通过；Linux 候选包由 Windows 交叉编译 |
| 目标平台 | `windows/amd64`、`linux/amd64`，`CGO_ENABLED=0`、`-trimpath`、`-mod=readonly` | 构建机版本与生产运行系统分别记录 |
| 安装脚本 | `.npmrc` 固定 `ignore-scripts=true`，正式入口再显式传参 | npm 未审查警告不是安全保证，禁止白名单和全量放行 |
| 可选平台包 | `npm ci` 显式包含开发和可选依赖 | esbuild 不执行安装脚本，使用锁文件中的平台包；外部二进制覆盖被拒绝 |
| 发布追溯 | `manifest.json` 的 `build_environment` | 包含实际工具链、系统、直接前端依赖、安装策略和五份输入文件 SHA256；Go 驱动及依赖由模块文件哈希追溯 |
| 源码换行 | `.gitattributes` 固定文本 LF，二进制自动识别并保留 | 覆盖用户 `core.autocrlf` 差异；原目录不强制重写，正式验证使用干净克隆 |

正式发布入口自动校验工具链、核验 Go 模块缓存、按锁文件干净安装，并在构建结束后复核输入文件。环境不符时尽早失败；构建中版本文件漂移则不生成发布清单。`toolchain.mjs` 和配套测试属于正式构建代码，不作为替代真实部署的辅助验收脚本。具体流程见 `build/README.md`。

## 三、迁移与降级边界

1. 三种数据库必须提供相同编号和名称的迁移，SQL 内容允许因方言不同而不同。
2. `migration_catalog_test.go` 检查源码目录、嵌入资源和 `latestMigrationVersion`；新增文件忘记登记或嵌入时必须失败。
3. `Migrate` 在执行后续迁移前读取完整有序版本历史；版本高于程序支持范围或历史不连续时拒绝启动，不自动删除或修补版本记录。
4. MySQL 的 DDL 重入和 PostgreSQL 的事务回滚必须用对应引擎验证，不能通过文件数量一致推断行为一致。
5. 当前不存在通用向下迁移承诺。降级须使用兼容程序及对应已验证备份，在隔离环境验证后再操作，禁止通过删除 `schema_migrations` 绕过拒绝。

## 四、真实实例验收步骤

每个数据库和声明支持的服务端版本独立执行以下步骤，保存版本、候选提交、命令退出码和脱敏证据：

1. 建立明确归属的隔离空库和最小权限账户，验证 TLS 与主机身份；不使用现有业务库。
2. 按正式初始化入口完成配置；创建用户、域名、DNS 账户、服务器和任务，验证权限隔离。
3. 从支持的旧版本数据库升级，检查数据、索引、默认值、归属和任务状态；重复执行不产生额外变更。
4. 注入迁移中断，在恢复后确认重入/回滚；新版数据库被旧程序拒绝且原数据保持不变。
5. 按该数据库的 CLI 备份恢复流程在另一隔离空库恢复；验证敏感配置和证书关联，篡改备份必须拒绝。
6. 重启服务验证持久化，完成前后端业务回归；记录未执行、跳过和失败项，不汇总为通过。

MySQL/PostgreSQL 没有当前实机证据的格子保持待验收。本矩阵不授权清理共享数据库或同机其他服务。

## 五、MySQL 隔离迁移正式回归

测试入口为 `backend/internal/database/mysql_integration_test.go`，实例生命周期由同目录的 `mysql_integration_helpers_test.go` 管理；属于正式 Go 测试，不需要辅助脚本。未显式提供程序目录时显示跳过，不得把常规 `go test ./...` 的结果当作实库通过。

本批 Windows 实际命令如下，两个版本分别执行；产物根可复用，但测试每次创建全新数据目录，不复用业务库：

```powershell
Set-Location D:\Desktop\Scert\backend
$env:SCERT_MYSQL_TEST_ROOT = 'D:\Desktop\Scert\artifacts\mysql-matrix-20260927'
$env:SCERT_MYSQL_TEST_BIN = 'E:\DB\5.7\bin'
go test -count=1 -v -timeout=8m -run '^TestMySQLRealMigrations$' ./internal/database

$env:SCERT_MYSQL_TEST_BIN = 'E:\DB\8.0\bin'
go test -count=1 -v -timeout=8m -run '^TestMySQLRealMigrations$' ./internal/database
```

安全和覆盖边界：

1. 只接受绝对程序及产物目录，不接受外部 DSN；使用 `--no-defaults`，不会读取既有实例配置。数据库管理命令只作用于本次创建的随机端口与数据目录。
2. 初始化不开放监听；首次启动在接收连接前设置随机密码。运行时仅绑定 loopback，强制 TLS，验证 CA 和 IP 身份；8.0 的额外 X 协议关闭。
3. 迁移使用库级业务账户，不用管理账户替代最低权限检查；测试保留管理账户仅用于创建隔离库和正常关闭自己的进程。
4. 每个历史起点及每个 DDL 中间状态升级后，比较表引擎、字段类型、默认值、字符集及全部索引。此比较证明升级结构与全新迁移一致，不单独证明业务设计本身完全正确。
5. 冷重启用例关闭应用连接池、停止数据库、重启后重新打开连接。开发阶段保留旧池时发现首次操作会报失效连接，在线恢复仍是待办，不用冷重启结果代替。
6. 测试正常结束会停止自己的进程，清空初始口令文件，保留日志和数据目录；产物已被 Git 忽略。非正常终止后应先核对具体进程归属，禁止批量停止所有 MySQL。
7. 本批不是发布包部署、Web 初始化、备份恢复、Windows Service 或 Linux 运行验收；PostgreSQL 和 SQLite 剩余矩阵不得据此标记通过。
