## 一、确认的需求与约束

- 全部 44 项整改范围保持不变；本轮从缺失的项目根实体开始，逐步接入原定全部核心资源。
- 项目不是用户分组：用户分组的现有展示与成员约束不能被解释为项目授权。
- 资源关联、项目成员授权和 HTTP 接口分别交付；授权闭环前不开放项目管理接口或项目全量列表接口。
- 历史迁移只能增加关联，不删除原任务、服务器、证书、凭据或审计。禁止凭项目种子存在就宣称历史资源已回填。
- 历史资源的默认项目 ID 固定为 `default`；已有默认项目名称和说明在迁移重试中不得覆盖。
- 非默认项目 ID 由后端生成；名称和说明可修改，项目 ID 与创建时间不能通过更新接口改写。
- 所有最终资源引用需要防止跨项目混用；不能仅靠前端筛选保证隔离。

## 三、第 10 号迁移历史记录

仅新增 `projects` 表和默认项目种子，不改写既有业务字段，不将不存在的资源归属伪装成已完成。

字段为 `id`、`name`、`description`、`created_at`、`updated_at`。项目名称允许重名，以 ID 区分；名称最多 128 个字符，说明最多 4096 个字符，拒绝无效编码和危险控制字符。MySQL 项目表显式采用 InnoDB 与 `utf8mb4`，支持中文和四字节字符。

SQLite、PostgreSQL 迁移与版本记录使用同一事务。MySQL 不承诺 DDL 事务回滚：建表和种子写入之后登记版本失败时，保留已执行部分，重试补全版本且不覆盖现有项目资料。

项目仓储提供创建、读取、列表、资料更新和删除。默认项目不能经仓储删除或重复创建；列表默认项目优先。创建/更新时间由仓储生成，更新不覆盖创建时间。第 10 号迁移交付时还没有业务资源引用项目；随后第 11 号迁移已接入域名和服务器引用保护，但不能推及尚未接入的其他资源。

## 六、第 11、12 号迁移的当前边界

第 11 号迁移为域名和服务器新增 `ResourceScope` 四字段，绑定表增加项目。HTTP 创建只取服务端会话身份，更新保留原始创建归属；普通更新不能迁移项目。历史所有者和操作者未知时为空，本地系统操作也不冒充用户。

SQLite 第 11 号迁移安装触发器，第 12 号迁移进一步保护替换冲突的目标行及隐藏行号，插入后检查剩余引用；不依赖 `foreign_keys` 或 `recursive_triggers` 开关。插入检查会读取绑定或资源索引，尚未做大规模性能准入，不据此提升性能整改项。无效历史引用拒绝迁移，不能擅自删除业务数据；触发器建立与版本登记失败必须回滚。

MySQL/PostgreSQL 第 11 号迁移建立项目外键与绑定复合外键，第 12 号只登记统一版本，不声称新增或验证两库特有的替换语义。项目字段和约束不是成员授权，现有跨项目列表、私钥、DNS 等权限门禁仍需单独交付。

## 八、任务与审计接口字段增量

本节说明 Scert 接口；同目录《后端接口说明文档.md》是 Smail 发信集成参考，不向其中混入 Scert 路由。

| 接口 | 新增响应字段 | 含义 |
| --- | --- | --- |
| `GET /api/v1/tasks`、`GET /api/v1/tasks/:id` | `scope_type`、`project_id` | 任务创建时的范围快照；已有 `operator_id` 保存实际 HTTP 发起人，后台任务为空 |
| `GET /api/v1/tasks/:id/attempts` | `scope_type`、`project_id` | 从父任务继承；缺少父任务的历史尝试返回 `unknown` 和空项目 |

`scope_type` 为 `project`、`system` 或 `unknown`；这些字段仅表达归属，不是访问令牌。登录审计使用本次认证成功的用户，失败不把请求声明或旧 Cookie 当成已验证身份；更新自身账户、改密导致会话失效后仍保存实际操作者，但不恢复旧会话。既有权限限制继续生效，新增项目成员权限尚未交付。

## 九、第 14 号迁移：成员、角色与实时判权基础

`project_members` 以 `(project_id, user_id, role)` 为主键，记录授予时间；允许一个用户在多个项目内拥有多个角色，不改变现有用户分组数量规则。三库迁移不自动创建成员，不推测历史授权。项目和用户被成员引用时禁止删除或改标识，必须先撤销成员关系；历史任务／审计仍沿用模式 13 的独立快照，不级联删除。

### 9.1 能力矩阵

所有有效项目角色都可读取其项目基本资料，其他能力如下；未列出的操作默认拒绝。

| 项目角色 | 授予的项目能力 |
| --- | --- |
| 项目管理员 `project_admin` | 本模块定义的全部项目能力，包括成员管理、任务取消；仍受普通账户不能读取完整私钥的上限约束 |
| 证书管理员 `certificate_admin` | 证书读取、管理；完整私钥读取还要求登录账户为普通管理员或超级管理员 |
| 部署管理员 `deployment_admin` | 证书元数据读取、服务器读取／管理、部署读取／执行／回滚；不授予证书私钥读取 |
| DNS 管理员 `dns_admin` | DNS 元数据读取、管理、凭据使用；凭据使用不等于导出明文密钥 |
| 审计查看者 `audit_viewer` | 审计及任务读取 |
| 只读用户 `read_only` | 证书、服务器、部署、DNS 元数据及任务读取；不授予审计、凭据使用或任何写操作 |

登录角色 `super_admin` 不是可授予的项目角色。只有当前状态为 `active` 的真实超级管理员可跨项目执行已定义操作；不存在的项目和未知操作即使对超级管理员也拒绝。普通管理员不因登录角色或同组身份获得项目能力。

### 9.2 仓储与并发边界

- `AuthorizeProject` 每次查询实际用户状态、实际项目及当前成员，不缓存会话中的角色或权限。撤销成员、停用账户、普通管理员降为普通用户后，下次判权立即采用新状态。
- `GrantProjectRole`、`RevokeProjectRole` 仅允许有效超级管理员或目标项目的项目管理员；授权条件与成员写入在同一条 SQL 中执行，防止应用层先查后写的间隙。MySQL 撤销使用自连接，不依赖不兼容的同表删除子查询。
- 未知角色、无效目标、禁用操作者及越权变更拒绝；重复授予不会产生重复关系。项目管理员可撤销自己的角色，之后不能自行恢复；有效超级管理员保留恢复能力。
- 判权结果不是长期许可。业务入口仍须从实际资源解析项目，并在执行副作用前重新判权；任务提交、排队、取消、重试及撤权竞态的完整接入尚未完成。
- 成员成功变更与审计已使用同一事务，具体边界见 9.4。成员管理接口、界面、分页、失败请求审计尚未交付。当前没有新开放项目 HTTP 路由；仓储方法不能直接作为无需会话验证的外部入口。

### 9.3 迁移与恢复边界

SQLite 使用外键和额外触发器保护关联，不依赖外键／递归触发器开关。插入前未指定行号时的 `-1` 不误拒绝正常新增，插入及更新后继续检查引用；扩展唯一索引造成的隐式删除也应回滚。邮箱冲突遵循既有非空邮箱唯一索引，多个空邮箱账户的正常新增和更新不受阻。触发器重名或版本登记失败，表与新触发器随事务回滚；不删除旧触发器强行通过。

MySQL 从历史 `users.id` 读取实际字符集和排序规则建立成员外键，不采用可能已变更的库默认值；DDL 后版本登记失败可重试，保留已有成员。重试检查用户字段、角色枚举、主键和双亲外键，残缺同名表拒绝登记版本，不自行删除或修补业务表。PostgreSQL 使用事务迁移与外键；本批未完成其原生实库验证。

Windows 独立产品程序已验证升级前的历史备份以及含两个项目角色的新备份恢复；恢复后重新走正式入口并核对成员授权及跨项目拒绝。此证据不是完整发行包、真实服务重启、三库全部恢复或生产验收。

### 9.4 成员变更与审计事务

- `changeProjectRole` 在同一事务内调用带实时授权谓词的成员写入和成功审计；不调用另开连接的审计接口，避免脱离事务或阻塞单连接 SQLite。
- 审计动作区分 `project_member.grant` 与 `project_member.revoke`，资源为目标账户，记录项目范围、实际操作者和角色；自我撤权后使用刚验证的变更上下文，不重新推测已失去的权限。
- 成员影响行数不是 1、审计写入失败、触发器忽略插入或提交失败均不得返回成功。审计插入未实际写入时回滚已发生的成员变更。
