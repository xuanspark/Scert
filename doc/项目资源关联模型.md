# 项目资源关联模型

> 本批最终验证：SQLite、MySQL 5.7/8.0 项目专项、3 次竞态检测、完整后端及独立 Windows CLI 备份恢复已通过；第五节保留测试启动时状态，最终以执行清单和支持矩阵第十八节为准。P0-06/P0-07 仍为 `[~]`。

> 对应 P0-06、P0-07、P0-10；2026 年 9 月 28 日建立。本文区分已实现模型与后续目标，不以建表代替权限验收。

## 一、确认的需求与约束

- 全部 44 项整改范围保持不变；本轮从缺失的项目根实体开始，逐步接入原定全部核心资源。
- 项目不是用户分组：用户分组的现有展示与成员约束不能被解释为项目授权。
- 资源关联、项目成员授权和 HTTP 接口分别交付；授权闭环前不开放项目管理接口或项目全量列表接口。
- 历史迁移只能增加关联，不删除原任务、服务器、证书、凭据或审计。禁止凭项目种子存在就宣称历史资源已回填。
- 历史资源的默认项目 ID 固定为 `default`；已有默认项目名称和说明在迁移重试中不得覆盖。
- 非默认项目 ID 由后端生成；名称和说明可修改，项目 ID 与创建时间不能通过更新接口改写。
- 所有最终资源引用需要防止跨项目混用；不能仅靠前端筛选保证隔离。

## 二、实体及持久化分批计划

| 实体 | 当前状态 | 后续关系与交付要求 |
|---|---|---|
| `projects` | 已新增模型、三库第 10 号迁移和 SQL 仓储 | 作为项目根实体，统一资源引用；尚无对外接口 |
| `users`、`roles` | 既有用户和角色实现；项目成员与角色分配待补 | 用户经项目成员关系获得权限，不能按用户组名称推导项目权限 |
| `domains`、`servers` | 既有业务表；尚未增加项目字段 | 增加项目、所有者、创建人和更新人；历史数据回填默认项目 |
| `domain_servers` | 既有绑定表；尚未校验项目一致性 | 同一部署绑定的域名与服务器必须属于同一项目，失败须保持原绑定 |
| `tasks`、`task_attempts` | 既有任务与尝试表；尚未增加项目隔离 | 项目及资源归属、执行人、幂等与任务尝试关联；执行前重新判权 |
| `certificates`、`certificate_versions`、`certificate_orders` | 证书业务已有实现；统一实体关系待补 | 项目、域名、订单、版本、任务和签发结果可追溯 |
| `dns_accounts`、`dns_delegations` | DNS 配置业务已有实现；统一实体关系待补 | 项目、所有者、凭据引用、委派及验证任务关联 |
| `deployment_targets`、`deployment_records` | 部署业务已有实现；统一实体关系待补 | 关联项目、服务器、证书版本、任务尝试和回滚记录 |
| `renewal_policies` | 续期业务已有实现；统一实体关系待补 | 关联项目、证书、计划和执行任务 |
| `notification_channels`、`notification_records` | 通知业务已有实现；统一实体关系待补 | 关联项目、事件、任务、通道和发送结果 |
| `audit_logs` | 既有审计表；尚未增加项目隔离 | 项目、操作者、资源、任务与危险操作结果可追踪；全局操作单独定义范围 |
| `backup_records` | 数据库备份恢复已有实现；统一实体关系待补 | 区分系统备份与项目备份，记录范围、校验及恢复任务，不泄露私钥 |

## 三、当前第 10 号迁移

仅新增 `projects` 表和默认项目种子，不改写既有业务字段，不将不存在的资源归属伪装成已完成。

字段为 `id`、`name`、`description`、`created_at`、`updated_at`。项目名称允许重名，以 ID 区分；名称最多 128 个字符，说明最多 4096 个字符，拒绝无效编码和危险控制字符。MySQL 项目表显式采用 InnoDB 与 `utf8mb4`，支持中文和四字节字符。

SQLite、PostgreSQL 迁移与版本记录使用同一事务。MySQL 不承诺 DDL 事务回滚：建表和种子写入之后登记版本失败时，保留已执行部分，重试补全版本且不覆盖现有项目资料。

项目仓储提供创建、读取、列表、资料更新和删除。默认项目不能经仓储删除或重复创建；列表默认项目优先。创建/更新时间由仓储生成，更新不覆盖创建时间。当前没有业务资源引用项目，因此普通项目的引用删除保护须随资源迁移一起实现，不能提前标记完成。

## 四、下一批关联迁移的验收条件

- [ ] MySQL 项目外键的引用字段采用与项目主键一致的字符集和排序规则，不因既有表默认配置不同而导致部分迁移失败。

- [ ] 域名、服务器、任务、审计等核心资源增加项目及归属字段，旧数据可确定地回填。
- [ ] 三库外键或等效强约束保持一致；项目不存在、跨项目关联、删除仍被引用项目必须拒绝。
- [ ] 域名服务器绑定的替换在同一事务中校验归属，失败不清空原绑定。
- [ ] 全部相关 SQL 查询、写入、扫描和后台任务同步处理项目，不能仅增加 JSON 字段。
- [ ] 原始证书、凭据、通知和备份状态全部能关联，禁止留下隐式共享全局资源。
- [ ] 两项目实测列表、详情、写入、导出、删除、回滚和撤权后的排队任务，覆盖 P0-07。
- [ ] 三库历史数据迁移、失败重试、备份恢复及独立发行程序验证完成后，再推进实机验收。
