# HTTP-01 验证部署说明

## 范围与前提

- 在托管域名的编辑窗口选择“HTTP-01（网站验证）”；历史域名和未指定方式的新域名默认 DNS-01。
- 单域名和不含泛域名的 SAN 证书可选择 HTTP-01。主域名或任何 SAN 包含泛域名均拒绝，不能自动降级或改用其他验证方式。
- 这是托管证书的验证方式，不改变管理后台首次初始化的 DNS 验证、管理证书信任或就绪检查要求。
- 域名的全部有效 A/AAAA 入口都必须将该域名 80 端口的挑战路径交给运行 Scert 的同一实例。多节点入口需统一反代到该实例，不能把挑战随机分配给独立进程。
- 不自动改动 DNS、不覆盖业务站点、不新增公网应用端口。证书推送服务器不是挑战服务，除非其对应站点明确反代挑战路径。

## Nginx 接入

1. 将 `deploy/nginx/http-challenge.conf.example` 中的 `__UPSTREAM_PORT__` 替换为 Scert 回环 HTTPS 端口，将 `__MANAGEMENT_HOST__` 替换为上游管理证书覆盖的域名。所有占位符需替换后再加载。
2. 将生成的片段放到仅管理员可写的绝对路径；在每个待签发域名**已有的 80 端口 server 块**中 include 此文件。没有站点的域名由管理员创建精确 server_name，不使用 default_server。
3. 不允许保留 server 级的重定向 return 或会提前改写挑战的 rewrite；将普通 HTTPS 跳转移到 `location /`。挑战自身不依赖申请目标域名已经有 HTTPS 证书。
4. 管理站点示例 `Scert.conf.example` 新增 `__HTTP_CHALLENGE_SNIPPET_PATH__`，填写上一步绝对路径。该示例只覆盖管理域名，不能当作所有托管域名已接入。
5. 保留原始请求 Host；TLS 的 SNI 单独使用管理域名。保留 `proxy_ssl_verify on` 和可信 CA，不通过关闭校验绕过上游错误。
6. 检查 Nginx 配置后重载。未知令牌应直接返回 404、无缓存、无 SPA 页面或重定向。实际订单必须通过正常公共 DNS 执行签发，固定 IP、hosts 映射及内部测试不能替代生产验收。

## 安全与生命周期

- 挑战按订单、域名和令牌隔离，只允许 GET/HEAD，不使用客户端的 X-Forwarded-Host 决定域名。
- 签发结束、失败、取消均清理订单；存储上限 4096 条，单挑战有效期 15 分钟。进程重启后不恢复过期挑战，未完成订单按既有失败与重试机制处理。
- 应用常规访问日志不记录挑战令牌，Nginx 片段关闭挑战访问日志；未知请求不回显敏感内容。
- HTTP-01 不读取或校验 DNS 凭据，但不会放开项目证书管理、部署、重试及执行前的实时授权。
- API 字段为 `challenge_type`，允许 `dns-01` 或 `http-01`。创建时缺省为 DNS-01；更新时省略字段保留现有方式；非法值拒绝。HTTP-01 保存时清空不适用的 `dns_provider`。
