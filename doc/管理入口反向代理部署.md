# 管理入口反向代理部署

## 适用范围

管理域名由部署者指定，不固定为测试域名。独立站点模板位于 `deploy/nginx/Scert.conf.example`，适用于已完成初始化并取得正式管理证书的 Linux 服务。

当前模板不提供管理证书自动续期、证书路径切换或服务重载机制。完成这三项的实现和故障测试之前，不应据此宣布无人值守生产部署验收通过。

## 当前测试参数

| 占位符 | 本次测试值 |
| --- | --- |
| `__MANAGEMENT_HOST__` | `web.apmmk.cn` |
| `__HTTP_PORT__` | `8003` |
| `__HTTPS_PORT__` | `8004` |
| `__UPSTREAM_PORT__` | `9004` |
| `__FULLCHAIN_PATH__` | `/ssl-scert-acceptance/web.apmmk.cn/single/20260917-V1.0/fullchain.pem` |
| `__PRIVATE_KEY_PATH__` | `/ssl-scert-acceptance/web.apmmk.cn/single/20260917-V1.0/key.pem` |

应用配置应保持 `server.https_mode=proxy`、回环监听 `127.0.0.1:9004`，并设置 `server.proxy_https_port=8004`。修改管理域名时，应同步调整应用域名、DNS、证书、Nginx 的 `server_name`、跳转地址和 `proxy_ssl_name`，不能只更改浏览器入口。

## 部署流程

1. 核对现有监听端口、Nginx 配置和同机服务。保留主配置及其他项目站点，不覆盖共享站点。
2. 备份配置并核对权限。使用模板生成独立站点，逐项替换英文占位符；检查没有残留占位符。
3. 确认证书覆盖管理域名且未过期，私钥受限。上游必须通过公共 CA 与主机名校验，不允许关闭 `proxy_ssl_verify`。
4. 执行 `nginx -t`，成功后才执行 `systemctl reload nginx`。检查失败时保留失败文件用于审查，但从有效配置加载目录移出，不重载服务。
5. 在主机防火墙及云安全组分别放行所需的 TCP 入口。本次为 `8003`、`8004`；管理后台应按实际使用范围限制来源。不要将上游 `9004` 对公网开放。
6. 核对 `systemctl is-enabled Scert.service nginx.service`。启用开机自启不等于完成主机重启演练。

`Host $http_host` 用于保留外部非标准端口。HTTP 跳转目标使用固定的配置域名，不使用客户端 Host 作为跳转目标；未知 HTTP 域名返回 404，未知 TLS SNI 拒绝握手。

## 验收流程

服务器内先验证 Nginx 与上游，不跳过 TLS 校验：

```sh
curl --noproxy '*' --resolve web.apmmk.cn:8004:127.0.0.1 \
  --fail --show-error https://web.apmmk.cn:8004/readyz
curl --noproxy '*' --resolve web.apmmk.cn:8003:127.0.0.1 \
  --head 'http://web.apmmk.cn:8003/login?acceptance=1'
```

预期分别是就绪响应和 308 跳转，跳转保留路径及查询参数。随后必须从独立公网主机与真实浏览器验证，不使用 `--resolve`、SSH 隧道或跳过证书校验掩盖入口故障。

桌面浏览器验收包括登录、刷新会话、退出后访问拒绝、静态资源和不同桌面宽度；协议验收包括 Cookie 安全属性、跨域写入拒绝和退出后的旧 Cookie 重放拒绝。使用新浏览器上下文，不复用其他项目缓存或会话。

若必须借助 SSH 隧道继续应用测试，应明确标记为隧道测试；即使浏览器全部通过，也不能等同公网部署通过。清理测试环境时只操作确认过的独立测试数据库，不清空共享服务器上的其他项目数据库。

## 剩余门槛

2026 年 9 月 17 日的具体结果见 `Linux生产流程测试记录.md`。本次 Nginx 站点内网验证成功，但独立 Linux 主机访问两个公网端口超时，尚需核对云安全组或上游网络。管理证书自动续期、更新后的双层 TLS 生效、故障回退以及真实目标机部署均需继续完成，不能将 `readyz=200` 作为完整验收结论。
