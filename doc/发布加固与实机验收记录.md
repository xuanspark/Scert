## 三、代码复审与安全加固

### 初始化与证书信任

`setup.Apply` 仅接受配置输入，不再直接标记 ready。HTTP 与 CLI 各自完成证书事务后才能提交就绪状态。CLI 初始化使用进程锁，取得锁后再次检查配置是否已存在。

新增 CLI 参数 `--acme-environment staging|production`，默认 `staging`。测试证书不被普通浏览器信任，不能用于生产。四个测试根来自 Let's Encrypt 官方仓库，仅用于测试签发结果校验；来源见 `backend/internal/certificate/trust/来源说明.md`。没有向操作系统、浏览器或 ACME HTTP 客户端添加测试根，也没有关闭正式证书链校验。

`cert.pem`、`fullchain.pem` 的叶子及私钥必须一致，不能只验证 fullchain 而忽略错误的单独证书文件。

### 远程部署事务

为每个规范化目标路径创建 `<path>.scert-lock` 目录，按路径排序获取。远程原子建目录可以让遵守该协议的不同任务和进程互斥；不能防止管理员或旧版本直接改文件。

无法确认临时上传文件所有权时，不自动删除该路径。备份目标已存在时拒绝覆盖。失败后用独立的 30 秒上下文重连、重新校验 SSH 指纹并回滚。文件回滚和服务运行态恢复是两件事：reload 已尝试后即使文件回滚成功，仍提示运行态需要核查。

### 安全依赖

本轮 `govulncheck` 检出 `golang.org/x/crypto v0.55.0` 的 `GO-2026-6354`、`GO-2026-6355`，调用路径涉及 `ssh.NewClientConn`。两项均为 SSH 通道死锁拒绝服务问题，按扫描建议升级至 `v0.56.0`。升级后必须重新全量测试、竞态测试并复扫，不能沿用升级前结果。

升级后 `govulncheck ./...` 与详细复扫均退出零：可达漏洞为零，已导入包的其他漏洞为零。模块层仍有 `GO-2026-5932`，属于未被本项目导入的弃用 `golang.org/x/crypto/openpgp` 包，无修复版本。本轮没有为消除该提示而删除仍需使用的 SSH 模块，不把“无可达漏洞”扩大为依赖树完全没有提示。

## 五、远程部署遗留锁与恢复流程

1. 停止针对这些目标文件的新任务，核实所有部署进程和管理员操作都已停止。
2. 记录目标路径、错误消息、事务 `BackupID`、临时路径和备份路径。不要复制私钥内容到工单或日志。
3. 确认原证书、完整链和私钥属于同一版本，检查内容、域名、有效期、属主及权限；私钥和私钥备份至少保持 `0600`，并确认业务服务的实际读取用户。
4. 回滚失败或状态不明确时，先从本事务备份恢复并重新校验。不要对整个证书根目录执行递归删除或递归改属主。
5. 文件恢复不等于运行态恢复。使用目标业务自身的配置验证命令；共享进程的 reload 必须获得对应维护授权。
6. 只有确认没有在途事务、文件已经一致且运行态处理完成后，管理员才能逐个移除已核实归属的空锁目录。禁止自动清理所有 `.scert-lock`，禁止根据锁目录年龄直接抢锁。
7. 无法确认创建成功响应的临时文件可能保留，即使本次业务文件已回滚也需要人工核查；不能按名称前缀批量删除。

## 六、正式升级与回滚门槛

1. 核对发布提交、`source_dirty=false` 和可信通道取得的归档 SHA256；解压到全新目录，再执行 `sha256sum -c SHA256SUMS`。
2. 确认域名在用户允许范围内，并分别验证当前 RAM 的读取、新增、删除能力。读取成功不代表可写，历史成功不是永久授权。
3. 确认管理机能以正常 TLS 校验连接正式 ACME 目录；不得借助关闭验证、随意更换 DNS 或修改未授权网络设施绕过。
4. 维护窗口内停止 Scert，按 `生产部署与运维说明.md` 创建包含配置、数据库、凭据和证书的完整备份，保留旧程序、Web 资源及服务配置。
5. 使用同一发布包更新核心程序、Web 资源与服务模板，先检查配置和本地健康，再检查 `/readyz`；不能为获取 200 手工伪造 ready 字段。
6. 初始化、实际 TLS、登录和授权链路通过后才接入真实业务推送。更新共享服务前单独获得维护授权。
7. 启动或验收失败时停止新版本，恢复经核验的旧程序、Web 资源及对应配置；如涉及数据变化，只使用已验证的完整恢复流程，不能只换二进制赌数据兼容。
