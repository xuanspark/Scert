## 三、复现与修复

### 1. 跨源登录、退出与初始化写入

原登录与退出接受跨源 `Origin` 或 `Referer`，并允许 `text/plain` 携带 JSON。跨源回归在修复前返回 200。仅限制初始化请求来自回环地址，也不能替代浏览器来源校验。

登录、退出、初始化提交和初始化 DNS 测试加入来源中间件；跨源返回 403，不设置或清除 Cookie，也不删除已有会话。同源和无来源头的既有 CLI/API 访问保持兼容。

### 2. 长操作完成后客户端却读到 EOF

普通 HTTP 写期限为 30 秒，而 DNS 等待和证书工作流明显更长。使用真实回环套接字，把普通写期限缩短为 50 毫秒、模拟 DNS 工作流延迟 150 毫秒，原实现稳定出现 EOF。

增加按路由配置的长操作中间件：DNS 使用其验证期限，证书操作上限 30 分钟，初始化外层 12 分钟。通过 `ResponseController` 调整响应写期限，并留出 2 分钟处理清理、回滚和结果序列化。普通请求的超时保护不变。新增取消后的明确响应测试。

**反向代理仍必须单独设置足够的读响应期限**。服务器放宽写期限不会自动改变 Nginx、负载均衡或客户端超时；本轮未修改远程代理配置。

### 3. 初始化阻塞所有配置读取

初始化原来在证书签发期间持续持有配置写锁。改为专用初始化互斥锁，加上开始和结束时的短配置锁。并发初始化返回 409；在模拟签发阻塞期间，状态请求仍可返回。

### 4. DNS 输入与旧响应串线

初始化及系统设置存在旧请求覆盖新输入、新结果的问题；系统设置对过期令牌和新增凭据检查不足。最初六个新增测试在修复前失败。

采用请求代次与同步输入监听，只有当前代次可更新结果、错误和加载状态。输入变化、关闭设置、组件卸载均使在途结果失效。新增配置必须有未过期的服务端验证令牌；未修改已保存 DNS 配置时仍可保存其他设置。

测试直接运行真实 Vue 组合式逻辑、监听和生命周期，模拟网络，不引入新 npm 依赖。**这些测试不是页面渲染或真实云 API 验收。**

### 5. 嵌套错误泄露

原 `RenewalReport.Errors`、阿里云报告 `Diagnosis` 和逐域 `Error` 能把底层错误带回客户端。新增哨兵错误测试在修复前失败。

保留失败数量、域名及写入和清理状态，返回安全中文诊断；未知 SDK 错误、受保护凭据读取错误不再直接拼接到响应。写入成功但清理失败仍明确显示 `writable=true`、`cleanup=false`、`verified=false`，不把脱敏误做成成功。

### 6. 登录状态长期增长和并发退出

三个新测试证明：过期且不再访问的会话未清理；随机账号可持续增加限流表；大体积账号输入直接留在限流键中。

改为：

- 新登录前回收过期会话，认证会话和失败登录表各设 4096 项上限。
- 限流表按请求触发、至少间隔一分钟回收过期项，不提前解除有效封禁。
- 账号规范化后散列为固定长度键，避免存储整段大输入。
- 会话表满时返回 503，不踢出有效用户；限流表满时未知键返回 429，不能悄悄绕过限制。
- 用户校验返回后再次检查会话存在性，避免已经完成的退出被旧刷新请求继续使用。
- 增加会话容量恢复和暂停账号查询期间并发退出的回归。

容量上限是内存保护，不是完整抗攻击方案。高并发认证、全局容量耗尽时正常用户可用性，以及可信代理下的来源限流，还需独立负载与攻击流量验收。

### 7. 阿里云入口与提示

全新初始化默认 `aliyun`，已保存的服务商仍保留。权限拒绝提示不再建议直接授予 `Action: alidns:*`，而是核对实际托管区并按失败动作补充必要权限，不扩大至所有域名。

这不代表整个产品已完成阿里云专用化。其他服务商的 UI 和兼容实现未删除。

## 五、仍需整改和生产验收的项目

### 发布阻塞

1. **阿里云写探测授权边界**：`AliyunAuthorizationChecker.Verify` 仍会从目标向父级候选逐级试写。应由用户明确托管区与允许操作范围，任何父区或公共后缀都不能因自动推断而获得操作授权。现有只读 `Inspect` 已是精确托管区模式，但不等于写路径已整改。
2. **当前管理环境未完成初始化和正式 TLS**：上轮文档记载 `/readyz=503 setup_incomplete`，正式 ACME 连接超时。本轮没有远程刷新，不能当作已解决或确认当前仍然如此。
3. **新代码未实机安装验收**：需要维护窗口、完整备份、受控升级、真实初始化、浏览器 HTTPS/SNI、正式证书链及回滚演练。
4. **真实业务推送未验收**：隔离 SSH/SFTP 事务测试不等于已有业务服务的实际证书读取、配置校验和授权 reload；`pcux.cn` 禁止修改仍然有效。

### 后续安全与质量工作

- 会话有效性校验对缺少 `UserID` 或 `PasswordHash` 的内部会话仍有兼容分支；真实登录会填写这两项，多个旧测试直接注入不完整会话。应先改测试夹具，再使生产分支严格失败关闭，不能把其当前状态称作完整认证审计通过。
- 长请求需要反向代理和实际客户端超时验证；后续宜评估异步任务接口，而不是继续提高所有请求的全局超时。
- 多用户、高并发、容量饱和与长时间运行尚未压力验收。
- Windows Service、Wails 安装包、ACL、MySQL 和真实防火墙链路需要各自目标平台验收。
