# DNS 多账户整改任务清单

## 需求与边界（2026年10月4日）

依据《Scert整改合并优化清单》和《核心能力任务规格》P1-03，以及用户已确认的 DNS 账户归属要求执行；不是新增需求。范围仅 Linux 与 Web，第一台部署业务，第二台只验收证书推送。公共域名切换和邮件授权尚待确认，不阻断本项开发。

- 独立保存多个 DNS 账户，显示项目和用户归属，不把固定系统账户列表视为完成。
- 支持账户创建、验证、禁用、轮换和安全删除；凭据保存在现有秘密仓库，不在接口、日志或审计输出明文。
- 域名显式选择账户；签发、自动续期和重试使用同一绑定及实时权限，禁止跨项目使用。
- 兼容旧系统账户，处理域名、任务和旧凭据引用，不在迁移时擅自删除历史配置或密钥。
- 处理账户变更与签发并发，验证结果只能更新对应凭据版本；禁用不能被旧验证响应覆盖。
- 页面保持一页可用；覆盖 SQLite、MySQL、PostgreSQL 迁移、权限与竞态，再做第一台正式部署和实机验收。
